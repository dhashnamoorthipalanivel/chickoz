User Roles & Credentials

The system has two roles with different access scopes. Admin has full control across all modules. Franchise users access only their own operational data and require an active subscription to log in.

Admin
System Administrator
Full access to all modules including subscription management, CRM, manufacture oversight, masters configuration, and all franchise data.
  • Manage all franchise subscriptions
  • Access CRM — Enquiry & Lead pipeline
  • Approve & dispatch Masala requests
  • Manage Kishok cart manufacturing
  • Configure all master data
  • View admin & franchise reports
Franchise
Franchise Operator
Access restricted to their own outlet's operations. Login is blocked when subscription is expired or suspended — shows a Subscription Expired screen.
  • POS billing and order management
  • Masala supply requests
  • Franchise menu availability settings
  • View own franchise reports
  • Subscription-gated access

03

Authentication

🔐
JWT-Based Authentication
Stateless Bearer token auth with role-based routing
Login Form→ POST /api/auth/login→ JWT Issued→ Token → localStorage→ Dashboard
  • Token stored in localStorage and attached to every API request via Axios interceptor
  • Role decoded from token: admin / super_admin → full access; user / franchise → subscription-gated
  • Subscription check runs on every layout mount for franchise users — expired/suspended blocks access with a branded error screen
  • Admin users bypass subscription check and enter immediately (synchronous localStorage check on mount)
04

Subscription Management

Admin-only module. Controls which franchise accounts can access the ERP. Each franchise must have an active subscription; expiry or suspension immediately revokes access.

🔑
Subscription Lifecycle
Admin enables, extends, suspends, and monitors franchise subscriptions
No Subscription→ Active→ Expiring Soon (≤7 days)→ Expired
Active→ Suspend → Suspended→ Re-enable → Active
Available Plans
Trial 14 days
Monthly 30 days
Quarterly 90 days
Half-Yearly 180 days
Yearly 365 days
  • Enable: Select plan, enter amount and start date — end date auto-calculates. Receipt generated on save.
  • Extend: By Plan or Custom Days — new end date stacks from current expiry.
  • Suspend: Confirmation modal with franchise ID/name. Re-enable available at any time.
  • Receipt Download: Print-ready HTML receipt in new tab with franchise details and payment date.
  • Auto-Expire: Server-side check runs before every read — subscriptions past endDate become EXPIRED automatically.
  • Payment History: Full ledger per franchise with receipt numbers, plan, days, and amount.

CRM — Enquiry & Lead Pipeline

The CRM pipeline converts a prospective franchisee from an initial enquiry through a five-stage qualification workflow before becoming a fully onboarded franchise.

📋
Enquiry Management
Initial contact capture with lead source tracking and follow-up scheduling
New→ Follow Up→ Converted to Lead
Hold·Cancelled
  • Auto-generated reference ID (e.g. ENQ-001)
  • Lead source tracking: Website, Instagram, Facebook, Reference, Walk-In
  • Package interest, follow-up date, assigned sales person
  • Convert to Lead action — locks enquiry and creates a Lead record with same reference data
  • Confirmation modals for Delete and Convert-to-Lead (blur overlay, spring animation)
📈
Lead Management — 5-Stage Wizard
Structured onboarding pipeline from site visit to franchise activation
1 · Site Visit→ 2 · Approval→ 3 · Training→ 4 · Payment→ 5 · Final Setup
Stage 1 · Site Visit
Visit type, date, and location captured. Map-based picker with 1 km geofence — prevents selecting a site too close to an existing franchise. Stores lat/lng coordinates.
Stage 2 · Approval & Legal
Site, approval, and legal status (all must be "Approved / Completed"). Dynamic document checklist from Masters → Document. Each document has checkbox and optional file upload.
Stage 3 · Training
Training status, start date, parent/guardian. Cart requirement — if Yes, captures cart size, amount, required date, priority, branding, accessories. Linked to Kishok module.
Stage 4 · Payment
Package amount, cart amount, GST %, total, advance, royalty type. Multi-payment entry — amount, date, payment mode, remarks. Paid vs. pending auto-computed. Pay Later option available.
Stage 5 · Final Setup
Contract signed, bank details, KYC upload, royalty document upload. Completing marks lead as Completed and triggers franchise account creation.
  • Lead View shows stage progress bar, all stage data, and payment history with mode names resolved from master
  • Lead status: Not Started → In Progress → Completed; manual override: Hold, Return, Cancelled
  • Franchise badge shown on lead row when franchise account has been created
06

Manufacture — Kishok (Cart Production)

Manages manufacturing workflow for food carts ordered by franchisees. Three stages: requirement capture, vendor assignment, and production tracking.

🛒
Cart Manufacturing Workflow
3-stage production pipeline from order to dispatch
1 · Requirement→ 2 · Vendor Assign→ 3 · Production
Pending→ Assigned→ In Progress→ Completed· Hold / Cancelled
  • Requirement Stage: Customer, phone, place, package, cart size/amount, branding, accessories, required date, priority (Normal/Urgent)
  • Vendor Assign Stage: Vendor name, phone, assign date, expected completion date
  • Production Stage: Manufacture status, dispatch date, cart image upload, remarks
  • Payment Tracking: Multi-payment entry with mode, date, amount. Paid vs. pending summary on view page
  • Receipt Download: Per-payment receipt printable from the view page
  • Can be created standalone by admin or linked from the Lead Training stage (cart required = Yes)

Manufacture — Masala Supply

Franchise users raise masala supply requests. Admin reviews, approves, processes, and dispatches. Full payment tracking per request.

🌶
Masala Request Flow
Franchise → Admin approval → dispatch → delivery
Franchise Side
Create Request→ Requested→ Under Review
Admin Side
Approved→ Processing→ Dispatched→ Delivered· Rejected
  • Franchise selects items from Masala Items master with pack size, unit, quantity, and auto-calculated amount
  • Payment option: Pay Now or Pay Later selected at creation
  • Payment status: UNPAID → PARTIAL → PAID, with full payment history (method, reference, date)
  • Admin dispatch screen captures transport name, tracking number, dispatch date, remarks
  • Status history log maintained for audit trail
  • Priority flag: Normal or Urgent — surfaced prominently in admin processing view

Masters & Configuration

Admin-only configuration area. All master records drive dropdowns, calculations, and constraints across every other module.

📁
Franchise
Outlet registration and profile
Franchise ID, owner name, contact, location, type. Soft-delete (isDeleted flag). Each franchise record can have an associated user account.
📦
Package
Franchise offering packages
Package type (Gas/Electrical/Both), cart size, cart amount, price, advance, royalty (percentage/fixed/none), menu items, agreement duration, GST, status.
🧾
Tax
GST and tax rate configuration
Tax name and percentage. Referenced by package pricing calculations in Lead Payment stage.
🍽
Menu Items
Product catalogue with franchise control
Menu items with base price and add-ons. Franchise Visibility controls which franchises see an item. Franchise Availability controls whether it's currently on sale.
🌶
Masala Items
Masala catalogue for supply requests
Item name, pack size, unit, price per unit. Franchise raises supply requests selecting from this master.
💳
Payment Mode
Payment method options
Payment mode names (Cash, UPI, Bank Transfer…) used in Lead Payment stage and Kishok payment entries. Stored as ID, resolved to name on display.
📄
Document
Legal document checklist
Documents configured here appear in the Lead Approval stage as a checklist. Each document has a name, type, and mandatory flag.
📢
Other Masters
Supporting configuration records
Lead Source — how enquiries originate
Order Type — Dine In, Take Away, Home Delivery
Material — raw material catalogue

Known Issues & Applied Fixes

All issues below were identified and resolved during active development. Each entry includes the root cause, affected file, and resolution status.

Severity Issue Root Cause & Fix Status
● High 401 Unauthorized on all API calls
apiClient.js
 Axios instance had no request interceptor — Bearer token was never attached. Fixed by adding api.interceptors.request.use() to read token from localStorage and set the Authorization header on every request. ✓ Fixed
● High Blank flash for all users on page load
MainLayout.jsx
 subChecked initialized as false caused return null on first render for every user including admins. Fixed by reading role from localStorage synchronously before useState — admins get subChecked = true immediately. ✓ Fixed
● High Subscription page not shown fully
Subscription.jsx
 Page had its own .page-content .container-fluid wrappers while MainLayout already wraps children in those same classes — creating double ~94px top padding (~188px total). Content was pushed below the fold. Fixed by removing the redundant wrapper. ✓ Fixed
● Medium Payment mode shown as raw MongoDB ID
LeadView.jsx
 The Lead View payment history table rendered p.paymentMode directly — a MongoDB ObjectId reference, not a display name. Fixed by fetching paymentModes from store on mount and resolving via .find(m => m._id === p.paymentMode)?.paymentName. ✓ Fixed
● Medium Suspend button used window.confirm()
Subscription.jsx
 The Pause/Suspend action triggered a browser-native confirm dialog — unstyled and inconsistent. Replaced with a custom modal matching the Enquiry "Convert to Lead" modal: purple icon, pulse rings, franchise info badge, Cancel/Suspend buttons with spinner. ✓ Fixed
● Medium Kishok view button showed edit color
Kishok.jsx
 The View action button used ckz-action-edit CSS class instead of ckz-action-view — making both View and Edit buttons appear identical in color. Fixed by correcting the class name. ✓ Fixed
● Low Lead view action button text invisible
LeadView.jsx
 The "Open Stage Workflow" button is a React Router <Link> element. Skote's global a { color } CSS override suppressed the inline color. Fixed by adding WebkitTextFillColor: "#fff" to bypass the cascade. ✓ Fixed
● Low Lead list double page-content wrapper
Lead.jsx
 Same double-wrapper issue as Subscription.jsx — Lead.jsx had its own .page-content .container-fluid inside MainLayout's identical wrapper. UI rebuilt to match Package module's compact style. ✓ Fixed
